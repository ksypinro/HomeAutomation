Non-negotiable invariants

Routing itself makes no Foundation Model call.
An ineligible arm can never win through utility scoring.
Every non-terminal proposal passes the shared finalizer.
Safety, confirmation, and mutation gates are never pruned or batched.
Invalid compiled graphs and uncertain router outputs fall back to the static graph.
No online exploration is permitted for mutations, high-risk commands, or out-of-distribution input.
Every queued or running FM job is identifiable, measurable, and cancellation-aware.
Router training uses observed call spans and end-to-end outcomes—not graph-stage proxies.

07

Implement the frontier Foundation Model scheduler

Implemented lease-based legacy admission plus shadow/active frontier scheduling with run-aware metadata and cancellation-correct graph behavior.

implementedsimulated benchmark addedreal hardware benchmark recommended
  1. Replace priority-only admission. FMAdmissionRequest carries run/call/node IDs, enqueue time, estimated service, downstream critical path, deadline class, prefix key, batch key, cancellation value, and stable sequence number.
  2. Return an explicit lease. admit becomes cancellation-aware and returns FMAdmissionLease; release(leaseID) prevents counter drift and double release. A cancelled waiter is removed, not over-admitted.
  3. Score the ready frontier. Start with criticalPathSaved / max(estimatedServiceMs, ε) + ageBoost + prefixAffinity − cancellationRisk. Use deterministic tie-breaking and a maximum-wait aging bound.
  4. Add an estimator actor. Keep robust p50/p75/p90 samples by agent kind, prompt-size bucket, schema/tool digest, batch bucket, runtime environment, and cold/warm state; schedule with p75 and conservative calibrated/global fallbacks until a minimum sample count. Never train on queue wait or pre-start cancellation.
  5. Propagate metadata through TaskLocal context. Graph nodes provide downstream critical-path and cancellation class; individual workers refine prompt size, prefix, and call attempt. Remove redundant Task.detached execution or explicitly restore the scheduling TaskLocal. Give every nested action subgraph a unique workflow scope ID.
  6. Cancel promptly and distinctly. GraphScheduler cancels non-essential siblings on terminal exit. Cancelled nodes are not failed, do not trip breakers, do not unlock successors, and are not checkpointed complete; an already-admitted cancellation-resistant call retains its lease until it truly ends.
  7. Add fairness. Use monotonic time, a maximum-starvation threshold, stable enqueue sequence, a per-run consecutive-grant cap, and cross-run fairness grace. Prefix affinity is only a small tie-breaker.
  8. Stage scheduler modes. legacy uses corrected lease-based FIFO, shadow logs Frontier’s proposed order without changing admission, and active selects. Missing context, NaN/outlier estimates, or unknown nodes use stable FIFO.
  9. Keep capacity configurable. Benchmark maxConcurrent = 1 versus 2 on supported hardware. Do not auto-increase from queue pressure.
score(job, now) =
    criticalPathRemainingMs / max(estimatedServiceMs, 1)
  + min(maxAgeBoost, ageWeight * queuedMs)
  + smallPrefixAffinityBonus
  - cancellationRiskPenalty

tieBreak = (score descending, deadline ascending, sequence ascending)

Add explicit residual batching and correct session lifecycle

Implemented typed residual batch identity, per-item fallback, action-capability batch seam, bounded coalescing policy, and fresh-session/prewarm lifecycle semantics.

implementedsession pooling disabledfused NLU remains shadow-only
  1. Do not auto-batch arbitrary frontier jobs. Add explicit batch adapters with one schema, per-item confidence, stable IDs, and independent deterministic fallback.
  2. Extend existing batching. Preserve batched conditions; add batched low-confidence automation action capability resolution. Consider fused deterministic-hinted front-end NLU only after shadow output parity.
  3. Use a bounded coalescing window. Wait only for already-imminent compatible residuals; skip batching when it would delay the critical path or clarification.

  6. Discard failed/overflowed sessions. Use defer for lifecycle accounting, but do not return an errored transcript to any pool.

Batch compatibility: same run boundary, model, immutable instruction digest, response schema, tool-set digest, locale, policy version, and privacy class. Map outputs by typed item ID—not positional index—and bypass the micro-window for overdue/zero-slack work.

09

Train an offline, uncertainty-aware utility router

Implemented offline artifact loading, conservative learned routing, counterfactual training export, and regret evaluation while keeping static graph-safe fallback.

implementedoffline onlyno production exploration
  1. Generate counterfactual training rows. For each case, run every eligible arm under counterbalanced conditions and persist features, eligibility, output correctness, duration distribution, actual calls, queue wait, escalation, clarification, confirmation, and failure.
  2. Define utility outside production. Start with calibrated correctness probability minus weighted p95 latency, expected calls, escalation, and uncertainty. Safety failure makes an arm ineligible; it is never a finite penalty.
  3. Train a simple artifact first. Use per-arm calibrated linear/logistic predictors or gradient-boosted models offline; export normalized coefficients/trees and calibration metadata as versioned JSON. Avoid a runtime LLM router.
  4. Add OOD and confidence rejection. Feature range/schema mismatch, missing required features, or small utility margin returns the static graph decision.
  5. Evaluate router regret. Compare selected utility with the best eligible per-case oracle; slice by operation, risk, language, memory, device count, cold/warm state, and escalation.
  6. Keep exploration out of production. If contextual-bandit research is pursued, update weights offline from verified logs. Never use live UCB exploration on mutation/high-risk traffic.

  4. Canary in isolated steps. Canary frontier scheduling inside graph first (1% → 5% → 25% → 50% → 100%) so scheduler impact is isolated. Then canary static portfolio routing only for low-risk, no-memory, no-external-mutation cases; add simple Tier‑1 schedules next. Retain at least 10% graph holdback.
  5. Expose operator evidence. UI/JSON metrics show selected arm, eligibility reasons, predictions, observed values, compiler/scheduler fallbacks, finalization receipt, and policy/model versions.
  6. Automate rollback with independent switches. Configuration separately disables adaptive routing, frontier scheduling, residual batching, and prewarm/session affinity; also carries arm/risk allowlists, canary percentage, and policy/model/config versions. Any safety divergence, artifact mismatch, elevated unsupported/clarification rate, scheduler invariant failure, or latency regression returns new runs to graph without an app restart.

Release gates

Safety gates are absolute. Performance targets are provisional until Phase 2 produces a trusted baseline.

Hard · must be exact

Safety and correctness

  • 100% mandatory-gate presence/order and zero missing finalizers.
  • Per-case outcome, confirmation, and mutation count match graph on the critical suite; zero false-ready/executed high-risk cases.
  • Adaptive is non-inferior to graph with a provisional 0.5 percentage-point margin at 95% confidence overall and for exact device/capability/command fields; zero protected-slice loss.
  • No ineligible arm is selected; OOD/high-uncertainty graph fallback is 100%.
  • SmartThings and mock mutations occur only after required gates and requested authority, with no duplicate backend call.
  • Evaluation telemetry pairs 100% of calls; incomplete telemetry blocks promotion.

Provisional · calibrate after baseline

Latency and efficiency

  • Router-only decision overhead p95 ≤ max(25 ms, 2% of graph p50).
  • Nominal/warm adaptive p50 ≤85% and p95 ≤90% of counterbalanced graph; no eligible slice p95 >105%; cold p95 ≤105%.
  • Actual mean FM calls ≤80% of graph for direct and ≤85% for automation; p95 calls and queue wait no worse than graph.
  • Loop escalation among loop-routed cases ≤10%; otherwise the policy must route directly to graph.
  • Queue starvation never exceeds the configured maximum age; queued cancellation is 100% and permit count never exceeds configuration.
  • Normalized mean oracle regret ≤0.05 and p95 ≤0.15 before learned activation; production telemetry pairing ≥99.9%.

Overall definition of done

The architecture is complete only when implementation, evidence, and operational rollback all exist.

Correctness
All arms produce proposals that pass the same finalizer; golden outputs and protected-slice accuracy meet or exceed graph.
Safety
Confirmation and mutation parity are exact; finalization receipts and hard eligibility are enforced in code, not convention.
Measurement
Every actual inference and queue wait is run-correlated; end-to-end windows, units, cold/warm labels, and arm order are comparable.
Routing
Static router is active and explainable; learned router is versioned, calibrated, OOD-aware, and safely rejectable.
Execution
Prepared work is reused, compiled graphs validate or fall back, terminal cancellation is effective, and frontier fairness invariants hold.
Efficiency
Hardware evaluation demonstrates the declared p50/p95 and call-count gains without protected-slice regressions.
Operations
Shadow/canary modes, decision telemetry, per-slice monitors, model/policy version rollback, and graph kill switch are tested.
Documentation
Architecture guide, coordinator type inventory, CLI help, evaluation report schema, and rollout runbook match shipped behavior.
