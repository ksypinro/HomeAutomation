05 · Proposed fourth orchestrator

Adaptive Portfolio + Frontier.

Choose the cheapest safe existing workflow for each request, compile only its necessary dependencies, and schedule scarce Foundation Model work by critical path, predicted job size, prefix state, and aging.

deterministic routerminimal DAGcritical-path FM frontier

Why this design fits

The repository already owns a portfolio of three reusable workflows and a comparison harness; routing among them is cheaper than asking another LLM to invent a plan.

01

Route before spending

Use deterministic features and hard coverage/safety constraints to avoid a loop that will predictably escalate or a full graph when Tier‑1 is sufficient.

02

Remove false barriers

Compile an input-specific dependency DAG so raw-text retrieval and deterministic work start as soon as their true inputs exist.

03

Schedule the bottleneck

Treat the on-device model as a scarce serialized resource. Prioritize work that shortens remaining critical path rather than whoever reaches a FIFO lane first.

Prerequisite

Apply the P0 safety and measurement fixes in the comparison review first. An adaptive router must never learn around missing safety gates or optimize against inaccurate call counts.

The algorithm

Six deterministic stages, followed by one shared finalizer and an offline feedback loop.

A · observeFeature snapshotCompute difficulty, ambiguity, coverage, risk, queue, and warm-state signals once.
B · constrainSafety allowlistRemove any arm that lacks coverage or mandatory final-gate parity for this request.
C · choosePortfolio routerScore graph, Tier‑1, loop, and an optional exact zero-FM template.
D · executeFrontier schedulerDispatch CPU tasks immediately; order FM residuals by downstream critical-path value.
E/F · finishBatch, cancel, verifyFuse compatible residuals, stop on terminal outcomes, run common safety finalization, log truth.

A · One deterministic feature pass

Compute operation and confidence, text length/language, action and condition counts, minimum field confidence, top-two candidate margin, unsupported fragments, condition precedence ambiguity, risk floor, memory-reference flag, RAG/model availability, FM gate depth, and cold/warm state.

B · Hard safety/coverage allowlist

Device-trigger automation can be drafted by the loop now that its specialists exist, but adaptive routing should still gate it behind finalizer parity and live telemetry. Unknown/OOD/ambiguous requests fall back to the broad graph. Model-unavailable requests use deterministic fallback. Safety failures are forbidden—not merely given a negative score.

C · Portfolio utility router

Start with auditable rules. Later learn an offline uncertainty-aware score:

U = P(correct) − λ·p95_latency − μ·FM_calls − ν·P(escalation)

Only score allowed arms. High uncertainty or out-of-distribution features choose the safe reference graph.

D · Minimal dependency DAG

Build from approved templates, then prune nodes whose facts are already high-confidence and cached. Remove the current all-to-all NLU/evidence barrier: for example, raw-text examples need not wait for risk classification.

E · Critical-path frontier

For each ready FM job, estimate service time and remaining downstream critical path. Rank by critical-path reduction per expected model millisecond, then add queue age and prefix/session affinity. Aging prevents starvation.

F · Batch, cancel, and learn

Fuse compatible residual fields that share schema/instructions, cancel non-essential work after clarification or terminal failure, run the same deterministic finalizer for every arm, and record verified outcome plus actual call-level telemetry.

Frontier scheduling in practice

Replace the static two-lane intent with a run-aware score while retaining bounded admission.

Suggested ready-job score

score(j) = criticalPathSaved(j) / estimatedServiceMs(j) + ageBoost(j) + prefixAffinity(j) − cancellationRisk(j)

Critical-path saved

Prefer a short verifier or condition call that unlocks final assembly over the first attempt of a long action subgraph with several downstream calls.

Estimated service time

Learn per worker kind, prompt tokens, output schema size, warm/cold label, and recent device performance. Benchmark model concurrency 1 versus 2 on actual hardware.

Prefix affinity

Prefer jobs that can use an already-prewarmed immutable instruction prefix. Do not reuse stateful transcripts across unrelated requests.

Cancellation risk

Deprioritize expensive work likely to be discarded if another ready branch may produce clarification. Cancel queued work the moment a terminal decision is committed.

Modern patterns considered

The proposed orchestrator combines ideas that transfer to this codebase and leaves infrastructure-specific claims at the boundary.

Peer reviewed · ICML 2024

LLMCompiler-style dataflow

A planner forms a dependency DAG and a task fetcher dispatches ready work. The paper reports up to 3.7× latency improvement over ReAct on its workloads; here the transferable idea is dependency-minimal parallel execution, not the numeric result.

LLMCompiler, PMLR 235 · 21–27 July 2024.
Peer reviewed · ICLR 2025

Learned utility routing

RouteLLM shows that a learned inference-time router can choose between stronger and weaker models while preserving benchmark quality at lower cost. HomeAutomation should route between complete workflows and explicitly add latency/escalation to the objective.

RouteLLM, ICLR 2025.
Peer reviewed · ICLR 2025 oral

Offline workflow search

AFlow uses execution feedback and Monte Carlo tree search over code-represented workflows. Use this only offline over approved templates, with latency/call count in the objective and mandatory validators locked.

AFlow, OpenReview · published 22 January 2025.
Primary research · 2023

Residual batching

Batch Prompting groups compatible samples in one inference and reports substantial time/token reductions on studied API workloads, while warning that decoding/runtime details matter. Extend existing condition batching to low-confidence action capability and fused NLU fields, then benchmark on Apple hardware.

Batch Prompting · 19 January 2023.
Emerging · 2026 preprint

Workflow portfolio selection

FlowBank curates complementary workflows and predicts query/workflow utility—the closest research analogue to selecting among this repository’s three prebuilt arms. Treat it as emerging evidence, not established practice.

FlowBank · 9 June 2026.
Emerging · 2025/2026

Difficulty and contextual-bandit orchestration

DAAO adapts workflow depth to query difficulty; CB-Orchestrator frames workflow selection as a contextual bandit. They support a future offline-trained, uncertainty-aware router after static rules and measurement are sound.

DAAO · CB-Orchestrator.
Emerging systems · 2026 preprints

Critical-path-aware serving

MARS, Pythia, and FATE expose workflow semantics, downstream critical path, warm prefix state, and future-ready work to a scheduler. Their server/GPU speedups do not transfer directly, but the ready-frontier scoring principle does.

MARS · Pythia · FATE.
Platform authority · Apple

Stateful sessions and real prewarming

Apple documents a session as a stateful context with a transcript, and separately exposes prewarm(promptPrefix:). Use immutable-prefix prewarming with at least a one-second lead; avoid cross-request transcript pooling and measure cache effects in Instruments.

LanguageModelSession · prewarm(promptPrefix:) · performance analysis.

What not to add for latency

Several fashionable agent patterns increase calls and are poorly matched to a closed, safety-critical home domain.

Adoption roadmap

Each stage is independently measurable and reversible.

0 · Establish truthful telemetry

Actual call spans, gate wait, end-to-end p50/p95, time to first token, cold/warm/thermal labels, randomized arm order, safety/accuracy parity, escalation rate, and router regret versus a per-case oracle.

1 · Apply no-regret fixes

Shared finalizer, deterministic/soft-timed loop root, seeded escalation, real prewarming and session isolation, priority labels, speculative diff reuse, early cancellation, and correct retry/required-node semantics.

2 · Ship a static conservative router in shadow

Use the table above, log its choice without changing user behavior, and compare with all three arms on the evaluation corpus and live hardware.

3 · Train an offline utility predictor

Begin with calibrated supervised predictions; optionally move to LinUCB or Neural-Linear UCB. Uncertainty/OOD always falls back to graph. No live exploration for mutation or high-risk cases.

4 · Add critical-path frontier and fused batches

Remove false barriers, estimate job duration, implement aging and prefix affinity, fuse residual NLU/action calls, and compare gate concurrency one versus two on actual devices.

5 · Optional offline workflow search

Use AFlow/FlowBank-like search only over approved templates. Every candidate must preserve mandatory gates, pass GraphValidator, and clear golden plus live-device suites before it enters the portfolio.

Claim discipline

Every latency gain on this page is a hypothesis until reproduced on supported Apple hardware with the real Foundation Model, correct telemetry, randomized arm order, and the same output/safety acceptance criteria.
