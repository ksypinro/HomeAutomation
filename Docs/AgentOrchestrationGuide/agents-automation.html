03 · Automation creation

Resolve a rule as independent components.

The current graph segments a request into trigger, actions, and conditions; resolves those components with bounded fan-out; assembles and validates a rule; then compiles or creates it through SmartThings.

Active automation graph

The graph is sequential at the stage level; the component fan-out node contains its own bounded parallel scheduler.

Verifier-loop workers

These are not HomeAgent graph nodes, but they perform agent-like specialist work in the second runtime mode.

DeterministicDraftPipeline

Input: command text and device registry. Process: deterministic parsing, scoring, target/capability inference, confidence table, and structural envelope assembly. Output: DraftEnvelope with command or automation fields. It makes no FM call.

DraftVerifierWorkerSession

Input: current envelope plus a bounded initial or delta prompt. Process: one constrained Foundation Model verdict using a reusable session; validates closed field IDs and dispute count. Output: accept, clarification, or typed disputes.

RepairPlanner + RepairSpecialistRegistry

Input: disputes, envelope, latches, and per-iteration budget. Process: groups disjoint fields by specialist, runs repairs in parallel, then merges in stable priority order. Output: repair results or a bounded escalation reason.

FragmentNLUWorkerSession

Input: disputed NLU field fragments. Process: deterministic hints plus an optional, soft-time-bounded FM repair. Output: a patch for only the disputed fields; target/risk/capability specialists cover their own field families.
